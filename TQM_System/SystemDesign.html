1. ผู้จองคิว

Booking Officer (ฝ่ายขายโชว์รูม)

สร้างคำขอจองคิว, ติดตามสถานะ, ขอแก้ใบจอง, รับใบจองเข้าปฏิทิน

2. ผจก.สาขา (SHR)

Branch Manager / Approver

อนุมัติเจ้าของรถ/รถเสริม + ใบจองคิว (ยืนยันตัวตน), ตั้งเกณฑ์ราคา, ยกเลิกได้

3. เจ้าของรถหลัก

Trailer Owner

ลงทะเบียนรถหลัก/เสริม, กดรับคิว, เลือกคนขับ, ดำเนินงาน 3.1–3.5, ปิดงาน

Accounting

Executive

แดชบอร์ดภาพรวม คิวสำเร็จ/ยกเลิก+สาเหตุ ดูได้หลายช่วงเวลา (Read-only)

6. Admin

System Admin

กำหนดตำแหน่ง User, เรทราคาตามพื้นที่, แนบระเบียบ/เอกสาร, ทำได้ทุกอย่างยกเว้น API

Brand Sales

1 ผู้จองคิว Booking Officer — เจ้าหน้าที่ฝ่ายขายของโชว์รูม

🧑‍💼

ผู้จองคิว

สร้างและติดตามคำขอจองคิวรถสไลด์
ตรวจสอบ & ประวัติ
  • เช็คคิวรถสไลด์ที่ว่างก่อนจอง
  • ดูประวัติการจองคิวที่ผ่านมาของตนเอง
สร้างคำขอจองคิว
  • ระบุข้อมูลให้ครบเพื่อจอง: ข้อมูลรถ · รูปภาพรถ · เซลล์ที่ขาย · จำนวนรถ · ปลายทางส่งมอบ (ปักหมุด GPS) · วันเวลาส่งมอบ บังคับครบ
  • กดยืนยัน → ระบบ ส่งคิวไปยังเจ้าของรถสไลด์หลักทุกราย (broadcast)
ติดตามสถานะ
  • ดูว่าคิวอยู่ขั้นใด: รอรับงาน / เจ้าของรถรับงาน / คิวรออนุมัติ → แก้ไขใบจอง → ผจก.อนุมัติ → งานบัญชีตรวจสอบ / อนุมัติใบจอง / กำลังดำเนินงาน / ปิดงาน / ถูกยกเลิก
  • ถ้าไม่อนุมัติ → ดูหมายเหตุในสถานะได้
  • เมื่ออนุมัติแล้ว → รับใบจองคิว + บรรจุลงปฏิทินตามวันเวลาที่คนขับนัดหมาย
ขอแก้ไขหลังอนุมัติ
  • ส่งคำขอแก้ไขใบจองถึง ผจก.สาขา พร้อมเหตุผล (เช่น ขออัปโหลดรูปรถใหม่)
  • ถ้า ผจก.อนุมัติคำขอ → แก้ไข + อัปเดตได้ทันที
  • ล็อกถาวรเมื่อเจ้าของรถหลักผ่านขั้น 3.1 แล้ว (แก้ไม่ได้อีก) Lock@3.1
ดูความคืบหน้าช่วงดำเนินงาน
  • ผ่าน 3.1–3.2 → “กำลังจัดเตรียมรถ” (ดูรูปภาพได้)
  • ผ่าน 3.3 → “กำลังเดินทาง” (เห็นพิกัด GPS เรียลไทม์)
  • ผ่าน 3.5 → “ส่งมอบเรียบร้อย”

2 ผู้จัดการสาขา (SHR) Branch Manager — ด่านอนุมัติหลัก

👔

ผู้จัดการสาขา (SHR)

อนุมัติ · กำกับ · ควบคุมเกณฑ์ราคา
การอนุมัติ (ยืนยันตัวตนทุกครั้ง)2FA/Identity
  • อนุมัติข้อมูลเจ้าของรถหลัก และรถเสริมที่เจ้าของรถหลักเพิ่มเข้ามา
  • อนุมัติใบจองคิวรถสไลด์ — ถ้าไม่อนุมัติต้องระบุหมายเหตุ (เช่น ข้อมูลไม่ครบ/กำกวม)
  • ถ้าไม่อนุมัติ → เด้งแจ้งเตือนกลับเจ้าของรถให้แก้ไข
  • อนุมัติแล้ว → ส่งใบจองต่อไปยังงานบัญชี
จัดการคำขอแก้ไข
  • อนุมัติการแก้ไขใบจองที่งานบัญชีอนุมัติจ่ายแล้วได้ · ดูรายการแก้ไขที่ส่งกลับมา
  • ยกเลิกการอนุมัติแก้ไข (ต้องระบุเหตุผล) → ข้อมูลใหม่ถูกยกเลิกการอัปเดต (revert)
  • ล็อกเมื่อเจ้าของรถหลักผ่าน 3.1
มองเห็น & ควบคุม
  • ดูรายงานภาพรวมทั้งหมด — คิวสำเร็จ/กำลังดำเนิน/ทุกขั้นตอนของทุกคิว
  • เห็นข้อมูลรถทุกคัน · เห็นข้อมูลการบัญชีรวมวันจ่ายในปฏิทินรอจ่าย
  • ติดตามคิวรถทุกคันเรียลไทม์ทุกขั้นจนปิดงาน
ตั้งค่า & ยกเลิก
  • เป็นผู้อัปเดตเกณฑ์ราคาตามระยะทาง ดูข้อต้องยืนยัน #1
  • ยกเลิกใบจองคิวได้เมื่อจำเป็น — ต้องระบุหมายเหตุชัดเจน

3 เจ้าของรถสไลด์หลัก (Trailer) Trailer Owner — ผู้เดินรถ

🚛

เจ้าของรถสไลด์หลัก (Trailer)

รับงาน · จัดคนขับ · ดำเนินงานภาคสนาม
ลงทะเบียนรถ (ต้อง ผจก.อนุมัติ)
  • ลงทะเบียนรถหลักของตน: ทะเบียน/ประกันคุ้มครอง/ใบขับขี่/ข้อมูลคนขับ/ยืนยันตัวตน/วันจด พ.ร.บ./ทุนประกัน/ข้อมูลรถ (แนบไฟล์ได้)
  • ลงทะเบียนรถเสริม (ฟิลด์ชุดเดียวกัน) · ต้องผ่าน ผจก.อนุมัติ
  • ต้องได้รับอนุมัติก่อนจึงเห็นระบบจองคิวส่วนผู้เดินรถ
สถานะรถ & รายได้
  • ดูสถานะรถหลักของตน · ดู/อัปเดตสถานะรถเสริม (ว่าง/ไม่ว่าง)
  • ดูคิวงาน/งานที่จบแล้ว — รายวัน/สัปดาห์/เดือน/6 เดือน/ปี หรือระบุวันเอง
  • แสดงยอดเงินที่ต้องได้รับ (นับเฉพาะใบจองที่บัญชีอนุมัติจ่าย + ปิดงานแล้ว)
รับคิว & สร้างใบจอง
  • มีคิวเข้า → แจ้งเตือน + เลือกรับ/ไม่รับ · ใครรับก่อนได้งาน คนที่กดทีหลังถูกปฏิเสธ
  • รับแล้วเห็น: ยี่ห้อรถที่สั่ง, จำนวนรถ, เซลล์ที่ขาย, ผู้จอง, ปลายทาง + เรทราคาที่จะได้รับ, วันเวลาส่งมอบ
  • เลือกคนขับหลัก/เสริมให้พอกับจำนวนรถ (ไม่พอ → เพิ่มรถเสริม ผ่าน ผจก.อนุมัติ) → ระบุวันเวลาเดินทาง → ขอสร้างใบจองคิว (ผจก.อนุมัติ)
  • ดูสถานะคิวว่าอนุมัติหรือยัง · ไม่อนุมัติ → เด้งเตือนให้แก้แล้วส่งใหม่
  • ได้ใบจอง → เห็นใบจองของตน + บรรจุลงปฏิทินตามที่นัดหมาย
ดำเนินงานภาคสนาม (กดเริ่มงานเมื่อถึงวันนัด)
ลำดับ 3.1 → 3.5 (เจ้าของรถหลัก + คนขับรถเสริมทำต่อรถที่รับผิดชอบ)
  1. 3.1 ถ่ายรูปก่อนขึ้นสไลด์ — หน้า/ข้าง 2 ข้าง/หลัง · AI ตรวจตรงกับรูปที่ผู้จองคิวบันทึกไว้ → ตรงจึงไปต่อ AI ผ่านแล้ว = ล็อกใบจอง
  2. 3.2 ถ่ายรูปขณะขึ้นสไลด์ — 4 มุม · AI ตรวจตรง → ไปต่อ AI
  3. 3.3 เริ่มจับ GPS จากต้นทางถึงปลายทาง · ผู้จองคิว/ผจก./เซลล์ ดูพิกัดปัจจุบันได้
  4. 3.4 ถึงที่หมาย → กดส่งมอบ · ถ้าปลายทางไม่ตรงหมุดเดิม ยังส่งได้แต่ต้องระบุหมายเหตุ และระบบคำนวณราคาใหม่ทั้งใบจอง+ปฏิทินจ่ายตามเกณฑ์ราคา Off-pin recalc
  5. 3.5 ถ่ายรูปหลังลงจากสไลด์ — 4 มุม · AI ตรวจตรง → กดปิดงานได้ AI
  • ปิดงานสำเร็จ → ระบบส่งแจ้งเตือน ดูข้อต้องยืนยัน #2

4 เจ้าหน้าที่งานบัญชี Accounting — ด่านอนุมัติจ่าย + PO/API

💰

เจ้าหน้าที่งานบัญชี

อนุมัติจ่าย · ปฏิทินรอจ่าย · ผูก PO
อนุมัติจ่ายใบจอง
  • รับใบจองที่ ผจก.อนุมัติแล้ว (มีเลขบิล + รายละเอียด)
  • อนุมัติจ่ายเงิน = ใบจองอนุมัติครบทุกขั้น · ไม่อนุมัติต้องระบุหมายเหตุ → เด้งกลับเจ้าของรถให้แก้
  • อนุมัติแล้ว → แจ้งเตือน + บรรจุลงปฏิทินตามนัดของผู้จองคิว/เจ้าของรถ
  • ดูประวัติการแก้ไขใบจองได้ทุกขั้น
ปฏิทินรอจ่ายเงิน & รอบจ่าย
  • บันทึกใบจองที่อนุมัติเข้าปฏิทินรอจ่ายเงิน
  • จ่ายจริงเดือนละ 1 ครั้ง — ตั้งได้ 1 วัน/เดือน (วันเดิมทุกเดือน หรือแก้ไขวันได้)
  • ดูปฏิทินรอจ่ายรายเจ้าของรถหลักแต่ละคนได้
ผูกเลข PO ผ่าน APIAPI บริษัท
  • เจ้าของรถปิดงานสำเร็จ → รายการในปฏิทินอัปเดตเป็น “ปิดงาน” เพื่อผูกเลข PO (จากระบบใบเสร็จเดิมของบริษัท ผ่าน API) ในวันจ่ายจริง
  • เฉพาะรายการสถานะปิดงานเท่านั้นที่ผูก PO เพื่อจ่ายได้
  • ยกเลิกใบจองที่อนุมัติจ่ายแล้ว → ยังแสดงอยู่แต่สถานะ ยกเลิก และผูก PO ไม่ได้
  • จ่ายจริงผ่านใบเสร็จที่มี PO ในระบบบริษัทแล้ว → ระบบ(ผ่าน API)เปลี่ยนสถานะเป็น ชำระเงินแล้วในงวดเดือนนั้น ดูย้อนหลังได้

🏷️

9 กติกา/กลไกสำคัญ (Cross-cutting) Key Business Rules

🔐 ยืนยันตัวตนทุกการอนุมัติของ ผจก.

การอนุมัติของ ผจก.สาขา (เจ้าของรถ/รถเสริม/ใบจอง/แก้ไข/ยกเลิก) ต้องยืนยันตัวตนเสมอ (เช่น OTP/PIN/ลายนิ้วมือ) — บันทึกลง Audit Log

🤖 AI ตรวจรูปรถ 3 จุด (3.1/3.2/3.5)

เทียบรูป 4 มุม (หน้า/ข้าง 2 ข้าง/หลัง) ที่คนขับถ่าย กับรูปอ้างอิงที่ผู้จองคิวอัปโหลด — ต้องตรงจึงไปต่อ/ปิดงานได้ ต้องนิยามเกณฑ์ “ตรง” — ดูข้อยืนยัน #3

🔒 ล็อกใบจองเมื่อผ่าน 3.1

เมื่อเจ้าของรถหลักผ่านขั้น 3.1 → ใบจองแก้ไขไม่ได้อีก (ทั้งผู้จองคิวและ ผจก.) เพื่อกันข้อมูลเปลี่ยนกลางงาน

✏️ คำขอแก้ไขหลังอนุมัติ (มี revert)

ผู้จองคิวขอแก้ (ระบุเหตุผล) → ผจก.อนุมัติ → แก้ได้ทันที · ผจก.ยกเลิกการอนุมัติแก้ได้ (ระบุเหตุผล) → ข้อมูลใหม่ถูก revert · เก็บ before/after

📍 ส่งผิดหมุด → คำนวณราคาใหม่

3.4 ถ้าปลายทางไม่ตรงหมุดที่ปักไว้ ยังกดส่งมอบได้แต่ต้องมีหมายเหตุ · ระบบคำนวณราคาในใบจอง+ปฏิทินจ่ายใหม่ทั้งหมดตามเกณฑ์ราคา

💵 จ่ายรอบเดือน + ผูก PO ผ่าน API

จ่ายเดือนละครั้ง (บัญชีตั้ง 1 วัน/เดือน) · เฉพาะรายการ “ปิดงาน” ผูกเลข PO จากระบบใบเสร็จเดิม (API) · จ่ายจริงแล้ว → สถานะ “ชำระเงินแล้ว” รายงวด

🚫 ยกเลิกหลังอนุมัติจ่าย

ยังแสดงรายการอยู่แต่สถานะ “ยกเลิก” · ผูก PO ไม่ได้ · เก็บเหตุผล+ผู้ยกเลิกไว้ในประวัติ (รายงานผู้บริหารเห็นสาเหตุ)

💲 เกณฑ์ราคาตามพื้นที่/ระยะทาง

เรทมาตรฐานเดียวสำหรับรถสไลด์ อ้างอิงจังหวัด/อำเภอ/ระยะทาง · ใช้ตอนแสดงเรทให้เจ้าของรถ + คำนวณ recalc เมื่อส่งผิดหมุด
